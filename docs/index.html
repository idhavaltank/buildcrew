BuildCrew is a human-led, evidence-first AI software engineering plugin for understanding projects, making focused changes, and reporting what was actually verified.

The BuildCrew loop

Instruction → context → reuse → smallest safe change → checks → evidence

Get started

BuildCrew works best when it can read the repository it is helping with. Open the project in your AI coding host, make sure its existing instructions are available, and have a specific task or question ready.

  1. Install the plugin or skillChoose the supported Codex plugin installation or a manual skill installation from the installation section below.
  2. Start a new sessionNew sessions load newly installed skills and prevent stale instructions from an earlier conversation.
  3. Begin with contextTell BuildCrew the goal, target area, constraints, and acceptance criteria. Ask it to inspect before editing.
  4. Review the planConfirm the scope and approach before asking BuildCrew to implement anything.
  5. Verify the resultAsk for focused tests or checks, then review the evidence and remaining risk.

Your first prompt

Use BuildCrew to inspect this repository and plan a small feature. Do not edit files yet.

Good practice: Start with a small bug fix or feature. It makes the workflow easy to evaluate and keeps the first feedback concrete.

Installation

BuildCrew is a plugin package containing the buildcrew skill. Use the native plugin path when available, or install the skill files directly.

Codex plugin

codex plugin marketplace add idhavaltank/buildcrew
codex plugin add buildcrew@buildcrew

Restart the Codex desktop app or start a new CLI thread. The current release is instruction-only and does not require lifecycle hooks.

macOS or Linux

mkdir -p ~/.codex/skills/buildcrew
cp -R skills/buildcrew/* ~/.codex/skills/buildcrew/

Windows PowerShell

New-Item -ItemType Directory -Force "$HOME\.codex\skills\buildcrew"
Copy-Item "skills\buildcrew\*" "$HOME\.codex\skills\buildcrew" -Recurse -Force

Project-local installation

your-project/.codex/skills/buildcrew/

Review before installing: A skill is instruction and resource content supplied to an AI agent. Read the files and understand any scripts or hooks before enabling an external package.

Trust rule: Never present a test as passing unless it actually ran, or imply that static inspection proves production behavior.

Workflows

Choose the workflow that matches the work. Routine changes stay lightweight; coupled or risky changes receive stronger checks.

Plan

Use BuildCrew plan mode. Inspect the repository and produce a bounded implementation plan for adding an empty state to the profile screen. Do not edit files.

Build

Use BuildCrew build mode to implement the approved plan. Keep the change focused and run the relevant checks.

Test and review

Use BuildCrew review mode to inspect this diff for correctness, security, missing tests, and unnecessary complexity.

Ship

Use ship mode when the implementation is complete and you need a final delivery summary, documentation check, release note, or handoff.

Escalate when needed: Security boundaries, data migrations, release configuration, shared abstractions, mobile platform behavior, and production-only behavior deserve broader verification.

Examples

Adapt these patterns to your repository and constraints.

Routine change

Small feature

Add an empty state to the profile screen. BuildCrew should inspect existing patterns, reuse project components, make the smallest change, and run focused tests.

Regression risk

Bug fix

Fix a retry loop that duplicates network requests. BuildCrew should trace the path, confirm the root cause, add a regression test, and report runtime risk.

New project

Do not invent architecture blindly. First ask about users, goals, core features, technology preferences, data, testing, security, and deployment expectations.

Undocumented project

Learn from source, configuration, dependencies, and tests. Record the documentation gap and avoid treating assumptions as facts.

Reusable prompt

Target: [project area]
Constraints: [important limits]
Acceptance criteria: [how success will be checked]

Completion response

  1. Summary: what was requested and what was done.
  2. Changed files: the files or areas that moved.
  3. Verification: commands, tests, inspections, or previews that actually ran.
  4. Not checked: relevant checks that did not run.
  5. Risk: assumptions, runtime limitations, or follow-up validation.

FAQ

Is BuildCrew a plugin or a skill?

BuildCrew is an installable plugin package that contains the BuildCrew skill. The plugin handles distribution and metadata; the skill contains the instructions the agent follows.

Does BuildCrew write code automatically?

Only when you ask it to build or edit. The recommended workflow begins with context and a plan.

Does it guarantee correct code?

No. It improves the workflow around understanding, implementation, and verification. It cannot prove production behavior that was not exercised.

Does it require lifecycle hooks?

The current release does not. It is instruction-only, so installation does not need hooks or background processes.
